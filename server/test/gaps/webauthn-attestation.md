# WebAuthn Attestation Validation Gap

## Summary

`parseAndValidatePasskeyCreation()` in `server/server/internal/auth/webauthn.ts` validates challenge and RPID but does **not** verify the WebAuthn attestation signature.

## Impact

An attacker who can submit a crafted passkey registration request can inject an arbitrary public key. The function extracts the key from untrusted CBOR and returns a JWK without verifying that the key was genuinely generated by a FIDO2/WebAuthn authenticator. Any `fmt` value (including `"none"`, which explicitly means no attestation) is accepted.

## What is validated

| Check                | Status |
|----------------------|--------|
| Client data JSON     | parsed & typed (arktype) |
| Challenge match      | checked against provided value |
| RPID hash            | SHA-256 of domain compared to authData[0..31] |
| AAGUID presence      | length check only |
| Credential ID length | bounds check |
| COSE key decode      | parsed as CBOR Map |

## What is NOT validated

| Check                | Status |
|----------------------|--------|
| Attestation `fmt`    | read but never enforced |
| Attestation signature | never parsed or verified |
| `verificationData`   | never constructed |
| Authenticator data integrity | not cryptographically verified |
| `aaguid`             | not checked against any allow/block list |

## Test evidence

Test `accepts crafted CBOR with an arbitrary public key (attestation NOT validated)` in `test/unit/auth/webauthn.test.ts` demonstrates that a completely fabricated attestation object with `fmt: "none"` and an arbitrary EC2 P-256 key is accepted. The COSE key bytes are arbitrary — no authenticator signed them.

## Remediation scope

Full attestation verification would require:

1. Parsing the `attStmt` from the attestation object CBOR per the `fmt` (e.g., `"packed"`, `"fido-u2f"`, `"none"`)
2. Building `verificationData` (authenticatorData + clientDataHash)
3. Verifying the signature in `attStmt` against the credential public key and `verificationData`
4. Rejecting `fmt: "none"` unless explicitly configured to allow self-attestation

This is deferred — see security backlog.
